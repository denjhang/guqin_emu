## 1. 数据模型（part-01.js，GUQIN_DATA）

古琴的几何被抽象成「弦长百分比坐标 gx」：
- `HUI_MARKS`：13 徽 = 弦长的等分点（七徽=49 即 1/2，五徽≈68 即 1/3，九徽=30 即 2/5……
  都是纯律/三分损益的自然泛音点）。
- `POSITIONS`（105 按音）：每弦每徽位的 {x: gx 百分比, freq, midi, 徽位名（含分数徽）}。
- `HARMONICS`（7×13）：泛音只存在 13 个节点上，音高=节点对应的谐波分频。
- `STRING_LINES`：每根弦的起止 y（琴面是梯形，弦距随透视变化）。
- 音域：正调定弦 C2~D3（散音 midi 36-50），按音到 midi 76，泛音到 86。

**要点**：所有交互都在 gx 坐标系（0~100 = 岳山到琴尾的弦长百分比）完成，再映射到像素。
频率一律精确记录，不查表计算。

## 2. 发声引擎 pluck()（part-07.js:1443）

点击一个音位后的完整链路：

1. **sampleKey()**：`open`(散)/`pressed:s:hui`(按)/`harm:h:s`(泛) → 对应一份真实录音。
2. **采样代理（surrogate）**（:1500 附近）：首次点击尚未解码的按音时不等解码，
   借用**同弦已解码、音高最近**的真实采样，以 `pos.freq / surrogate.freq` 校正
   playbackRate；后台继续解码本位采样，下次回到原音源。避免任何合成音替代音头。
3. **音准修正**：按音有逐音人工审核过的 `SM.tuning[key]` 倍率（part-02），散音不变速。
4. **同位重触**（:1528）：同 key 再次触发时旧 voice 30ms linearRamp 归零 + stop，
   防止叠加爆音。
5. **绰/注**（:1550）：用 playbackRate 的 exponentialRamp 实现滑音起手——
   绰 = 从下方大二度（`rate * 2^(-2/12)`）0.72s 滑到正位；注 = 反向。参数 CHUO_SEMI=2,
   CHUO_SEC=0.72。
6. **余音延长 stableSustained**（:1293, makeStableTailBuffer :1209）：
   真实录音只有 ~2.4s，长音如何续？
   - 取音头后 0.48s 窗口做**加谱分析**（每谐波用递推复振荡器做 DFT，H≤32 谐波）；
   - 用正弦递推（每 2048 样本归一化防漂移）**重合成**任意长的稳定余音；
   - 高频谐波滚降（按音 1500→3200Hz 余弦滚降）+ h>2 谐波指数衰减 `exp(-0.18*(h-2)/sr)`
     模拟真实消散；
   - 原声与合成声在 join 点做 **320ms 交叉淡化**，RMS 配平（0.08s 窗口）；
   - 基频优先用 lockedF0（目标频率÷tuning 倍率），不信任自相关——某些按音
     二三次谐波比基音强，自相关会选错峰产生"嗡/啾"接缝。
   - 性能：缓存 `stableTailCache`，key 含长度/类型/f0。
7. **「撞」的手工分段**（:1456 注释）：一条录音按音高转折切成三段
   (0-0.68s 音头 / 0.68-1.02 滑上 / 1.02-末滑回)，每段 12ms 淡入 60ms 淡出，跟手播放。

## 3. 走手音（滑音）与 morph

- **按音拖拽**（freeTap → startFreeGlideBody :3685）：6 秒音身，音高跟 gx 实时变——
  本质是 playbackRate 连续调制（gx→freq 线性映射到徽位刻度，不是等程直线性，
  因为按音位表本身就是物理弦长位置）。
- **「上/撞」morph 双振荡器**（startMorphGesture :1413）：
  - 两端各取一条真实录音，`morphWave()`（:1319）各分析出 PeriodicWave
    （H≤24，1300→2700Hz 滚降 + 高次阻尼 + RMS 配平 0.72~1.45）；
  - 两个 OscillatorNode 分别 setPeriodicWave(start/target)，音头 0.32s 真录音，
    0.31~0.66s 交叉淡入振荡器音身；
  - 手指位置 = progress u∈[0,1]：`ga=cos(u·π/2), gb=sin(u·π/2)` 连续混权，
    频率 setTargetAtTime(0.012s) 平滑——**手停声停，录音永远不会自己演完**；
  - **morphFriction**（:1368）：换向时叠加一条真实擦弦噪声（zhuang.wav 变速 2.15~2.25×，
    带 HP720/LP3300 滤波 + 18ms 起振包络），方向反转才触发——这是滑音"沙沙"质感来源。
- **散手纵向扫弦**（advanceVerticalStrum :3786）：
  - 先判手势合法性：纵向位移 ≥ 0.38 弦距 且 > 1.15× 横向位移，否则不算滚拂；
  - 逐帧检测指针跨越了哪些弦线（fromY→py 区间内的 lineY），按运动方向排序；
  - 每弦 42ms 防抖；散音给 openPos，泛音给 nearestHarm(gx)；
  - 手指移动途中跨多弦时一次补齐（解码等待期的 move 不丢）。

## 4. 录制/回放（事件流格式）

world-recorder.js 记录的事件（api-data/full.json 可见实例）：
```json
{"type":"pluck","t":2605,"pos":{"string":1,"x":49,"freq":130.813,"open":false,
 "harm":true,"hui":"7","huiLabel":"七徽","n":"1","o":-1},
 "soundMode":"harmonic","gain":0.72,"duration":61,"glide":[]}
```
- t=相对开演毫秒；pos 完整保留 gx/频率/徽位；glide 数组存滑音轨迹点。
- 回放（world-replay.js）= 按时间表 setTimeout 派发 + 调同一 pluck 引擎重演。
  关键工具 `later()` 把计时器收集起来便于整体取消；`resolvePosition()` 兼容旧格式。
- 这就是「社区分享」的全部数据量：一首曲子只有几 KB JSON。

## 5. 音游判定（打谱模式）

- 参考 bemuse 时钟 + 分档判定窗、Arcaea 计分、osu! 落速（part-07 头部自述）。
- `judgeReach(note)`（:2404）按音速给判定窗；`settle(note, errMs, t)`（:3491）结算；
  点早/晚在同弦上有 off-beep + 「早了/晚了 Nms」反馈（OFF_WINDOW=2.5 gx 单位内）。
- 谱面数据 `GUQIN_CHART` = {弦, 徽位, 时值, 触弦法, 减字谱字形 id}，带音位表校验，
  无真谱时回退「随机五音」——但随机也讲句法：先抽小节型（半半一/一长/…），
  再按「勾挑相间、外弦内弦交替、按音弦号跳变≤2」填音（v1.21 注释）。
- 三档难度只改 BEAT_SEC（=BEAT_BASE/rate）与提示显隐，谱面与判定完全一致。
- 泛音收煞双音：六弦+一弦七徽泛音同发（差两个八度），0.35s 判定窗，搭子没跟上
  只降档不判错。

## 6. 其他值得注意的工程细节

- **时钟**：一切以 `clock.time` 为准；暂停时记表、恢复整体后移，AudioContext
  suspend/resume 真停声。
- **性能**：谱分析用正弦递推替代逐样本 sin/cos；morphWave/长余音全部缓存；
  采样懒解码 + 并发去重（loadSample :1030）。
- **修过的坑（注释即文档）**：AudioBufferSourceNode.buffer 只能赋一次（v1.7 先赋
  原采样再换烘焙 buffer 导致长音全哑）；三弦一徽与十三徽物理对称共用一份采样，
  需要单独去噪且禁止进延音生成。
- **无障碍/嵌入**：`html.world-replay` 回放屏只看不弹；`?embed=home` 嵌页模式；
  dataset 上挂调试状态（guqinStrumCount 等）供自动化测试。

## 7. 可复用结论（若要自研同类模拟器）

1. 坐标系用**物理弦长百分比**，徽位=弦长等分点，频率硬编码自实测。
2. 音色三件套：真实采样音头 + 加谱合成余音 + 噪声擦弦层；滑音 = 双端音色
   morph（PeriodicWave 连续混权）而非单纯变调。
3. 演奏记录用事件流（pos 完整 + glide 轨迹），天然支持分享/回放/再分析。
4. 音游化只需要在事件流上叠一层判定窗；难度只动时间轴。
